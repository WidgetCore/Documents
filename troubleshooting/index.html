Troubleshooting

Fixing common WidgetCore problems — installation and activation, missing widgets in the editor, search returning no results, styling issues, FAQ behaviour, updates and performance.

Last updated 8 October 2026

This page collects the problems reported most often, with the quickest way to confirm each cause. Work top to bottom: most issues are resolved in the first two sections.

Widgets missing in the editor

  1. Confirm Elementor is active

    The widget category is registered on an Elementor hook; without Elementor nothing appears.

  2. Search the panel

    Type “WidgetCore”, “faq”, “search” or “comments” in the widget panel search.

  3. Check for a category filter

    Some themes or addons hide categories; look for a filter in the panel.

  4. Hard refresh the editor

    Ctrl + Shift + R (Cmd + Shift + R on macOS) clears the editor cache.

  5. Regenerate Elementor CSS

    “Elementor → Tools → Regenerate CSS & Data”.

Quick REST diagnosis

Open the endpoint directly in a browser:

ResponseMeaningFix
A JSON array of resultsThe endpoint works; the problem is in the widget settingsCheck “Source”, “Date filter” and the term filters
[] (empty array)The query matched nothingTry another term, or widen the source
rest_missing_callback_paramThe q parameter is missingAdd q to the request
rest_invalid_paramq is shorter than 2 characters or is not textAdd a longer q
rest_cannot_accessThe REST API is blockedCheck security plugins and server rules
A 404 pagePermalinks are not set“Settings → Permalinks”, save once

Then repeat the same request from the browser's network tab while typing in the widget, and compare the URL, the status and the response headers.

Performance

SymptomCauseFix
Slow first keystroke responseA heavy query (rand, a big tax_query, an unindexed meta_query)See the query and filters page
Large payloadslimit too high, or thumbnails onLower “Items per page”, or turn thumbnails off
Slow with a custom templateThe template is rendered per result on the serverKeep 6 to 9 items per page
Many image requestsThumbnails at full sizeUse a smaller registered image size in a custom template
Repeated identical queriesNo cachingCache the route response for anonymous visitors

Measure first

Open the network tab, run a search and look at the /wp-json/wgcr/v1/search timing. If the server response is slow the query is the problem; if the response is fast but rendering lags, the markup or images are.

Quick diagnosis checklist

  1. Elementor is active and the category is visible

  2. The endpoint answers: /wp-json/wgcr/v1/search?q=test

  3. The widget's Source matches the content you expect

  4. No JavaScript errors in the browser console

  5. Caches cleared and the asset version is the current plugin version

  6. debug.log has no fatal errors

If all six pass and something still misbehaves, note the plugin version, WordPress version, Elementor version and the exact steps, then open an issue on the GitHub repository — that information is what makes a report actionable.
