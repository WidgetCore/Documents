Requirements and compatibility

Minimum WordPress, PHP and Elementor versions for WidgetCore, the verified compatibility matrix, and hosting notes such as the REST API, mbstring and caching.

Last updated 2026-09-26

Read this page once before installing. Every value here is the same value declared in the main plugin file header (widgetcore.php).

Why Elementor is required

All widgets extend Elementor's Widget_Base class and are registered on the elementor/widgets/register hook. If Elementor is inactive the widget files are never loaded, so the plugin adds no output and no overhead to your site.

What your server needs

A working REST API

The live search fetches results from /wp-json/wgcr/v1/search. If another plugin or a security rule blocks the WordPress REST API, search shows an error message. A quick check:

The response should be a JSON array of results. If you get rest_cannot_access or an error page, the REST API is blocked.

Multibyte string support

The search query uses mb_strlen to enforce the minimum query length (2 characters). The function exists in standard PHP installations; if your host disabled mbstring, search will not work.

Page caching

The plugin installs no page cache of its own and works fine alongside caching plugins, because every search request goes to the REST API and cached page HTML has no effect on it. Two things to keep in mind:

  • If a server-level cache (such as Varnish) strips the X-WP-Total and X-WP-TotalPages headers, numbered pagination cannot build the full page list.
  • search.css and search.js are registered with the plugin version number (WGCR_VER), so after every update browsers fetch the new files and you never need to purge the cache by hand.

Translations are loaded on the init hook at priority 1, and the global wp-content/languages/plugins/ directory is read first — meaning a translation you place there is loaded before the bundled one. This behaviour is explained on the language and translation page.

Not covered

Things the plugin does not handle

  • Multilingual search in one widget: each widget searches one source (post type). On multilingual sites, place a separate widget per language.
  • Custom relevance weighting: the query is built on WordPress' own s parameter. For advanced scoring, use the wgcr_search_query_args filter (see query and filters).
  • Classic editor or Gutenberg blocks: the widgets are built for Elementor. In other builders only the [wgcr_search] shortcode is available.

Pre-install checklist

  1. Check your WordPress and PHP versions

    Both are shown under “Tools → Site Health” in the dashboard.

  2. Activate Elementor

    Without it, the “WidgetCore Widgets” category never appears in the editor.

  3. Test the REST API

    Open /wp-json/ in a browser; you should see JSON.

  4. Install the package

    Follow the installation guide.
