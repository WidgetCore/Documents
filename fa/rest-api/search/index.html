REST API جستجو

مرجع کامل مسیر REST جستجوی زنده؛ همه‌ی پارامترها، شکل پاسخ، هدرهای صفحه‌بندی، نمونه‌های curl و جاوااسکریپت و نکات امنیتی.

آخرین به‌روزرسانی 2026-09-30

نتایج جستجو از یک مسیر REST داخلی وردپرس می‌آید. این مسیر برای استفاده‌ی خود ویجت ساخته شده، ولی عمومی و مستند است؛ پس می‌توانید برای اپلیکیشن، ابزارک سفارشی یا اسکریپت خودتان هم از آن استفاده کنید.

نقطه‌ی پایان

موردمقدار
فضای نامwgcr/v1
مسیر/search
روشGET (READABLE)
دسترسیعمومی (permission_callback = __return_true)
وضعیت نتایجفقط publish و بدون رمز

این نقطه عمومی است

هر کسی می‌تواند بدون ورود به سایت از این مسیر استفاده کند. داده‌ای که برمی‌گردد همان چیزی است که در جستجوی عمومی سایت دیده می‌شود (نوشته‌های منتشرشده و بدون رمز)، پس نشتی اطلاعات وجود ندارد؛ اما اگر سایت شما نیاز به محدودسازی REST دارد، باید در سطح سرور یا با افزونه‌ی امنیتی همین مسیر را هم محدود کنید.

این محدودیت‌ها مربوط به کوئری پیش‌فرض‌اند. فیلترهای سفارشی wgcr_search_query_args بعد از ساخت آرگومان‌ها اجرا می‌شوند و می‌توانند آن‌ها را تغییر دهند؛ post_status => publish، has_password => false، پست‌تایپ عمومی و قابل جستجو و سقف مناسب را حفظ کنید. مسیر عمومی بعد از فیلترها این محدودیت‌ها را دوباره اعمال نمی‌کند.

پارامترها

پارامترنوعپیش‌فرضتوضیح
qرشته—الزامی؛ عبارت جستجو با حداقل 2 نویسه
typeرشتهpostیک پست‌تایپ عمومی و قابل جستجو؛ به‌جز attachment و elementor_library؛ مقدار نامعتبر به post برمی‌گردد
limitعدد5تعداد نتایج؛ بین 1 و 50 محدود می‌شود
templateعدد0شناسه‌ی قالب المنتور برای رندر نتایج
pageعدد0شماره‌ی صفحه؛ وقتی بزرگ‌تر از صفر باشد هدرهای شمارش برمی‌گردند
orderbyرشتهrelevancerelevance, date, title, author, rand, menu_order. rand در هر درخواست دوباره مخلوط می‌شود؛ همراه page ممکن است نتیجه‌ای در صفحه‌ی دیگر تکرار شود یا جا بیفتد
orderرشتهDESCASC یا DESC
dateرشتهallall, week, month, year

اعتبارسنجی q: اگر رشته نباشد یا طول آن پس از trim کمتر از 2 نویسه باشد، پاسخ خطای rest_invalid_param برمی‌گردد.

شکل پاسخ

پاسخ یک آرایه‌ی JSON از نتیجه‌هاست:

فیلدتوضیح
idشناسه‌ی نوشته
titleعنوان بدون برچسب و با رمزگشایی نهادها
linkپیوند یکتا
thumbنشانی بندانگشتی در اندازه‌ی thumbnail یا رشته‌ی خالی
excerptخلاصه‌ی 18 کلمه‌ای با نقطه‌چین (از post_excerpt یا متن نوشته)
dateتاریخ با قالب تنظیم‌شده‌ی سایت
htmlفقط وقتی template داده شود و قالب محتوای قابل‌مشاهده بسازد

شش فیلد پایه همیشه در پاسخ هستند. کنترل‌های نمایش thumb و excerpt فقط رندر مرورگر را تغییر می‌دهند، نه پاسخ REST؛ پارامتری برای حذف این فیلدها وجود ندارد. خلاصه از متن بدون تگ و شورت‌کد، با حداکثر 18 کلمه و رمزگشایی نهادها ساخته می‌شود؛ نقطه‌چین فقط هنگام کوتاه‌سازی افزوده می‌شود. تاریخ نمونه صرفاً نمایشی است. منبع داخلی «همه‌ی پست‌تایپ‌ها» وجود ندارد. html فقط با قالب منتشرشده‌ی elementor_library، المنتور فعال و خروجی قابل‌مشاهده برمی‌گردد.

وقتی template معتبر باشد، هر نتیجه علاوه بر فیلدهای بالا یک فیلد html دارد که خروجی رندرشده‌ی همان قالب برای همان نوشته است. اگر قالب پیش‌نویس باشد یا محتوای قابل‌مشاهده نسازد، html برنمی‌گردد.

رفتار سمت سرور

no_found_rows

وقتی page داده نشود (یا کمتر از 1 باشد)، کوئری با no_found_rows => true اجرا می‌شود؛ یعنی وردپرس شمارش کل نتایج را انجام نمی‌دهد و پرس‌وجو سریع‌تر است. به همین دلیل هدرهای X-WP-Total فقط در درخواست‌های صفحه‌بندی‌شده معنا دارند.

کدهای پاسخ

وضعیتمعنا
200موفق؛ آرایه‌ی نتایج (ممکن است خالی باشد)
400نبود q: خطای rest_missing_callback_param؛ کمتر از 2 نویسه یا نوع اشتباه: rest_invalid_param
404REST API غیرفعال یا مسیر نادرست
5xxخطای سرور؛ استثنای رندر قالب به‌طور جداگانه مدیریت می‌شود و در آن حالت فقط html حذف می‌شود

محدودسازی و بهینه‌سازی

  • کش: کل query string باید در کلید کش REST لحاظ شود و هدرهای صفحه‌بندی حفظ شوند. نتایج پیش‌فرض عمومی‌اند؛ اگر با فیلتر سفارشی به کاربر وابسته شدند، کش مشترک نگذارید یا زمینه‌ی کاربر را هم لحاظ کنید.
  • نرخ درخواست: افزونه هیچ محدودسازی نرخ (rate limit) داخلی ندارد. اگر سایت پرمراجعه است، در سطح سرور (مثلاً Nginx یا WAF) برای /wp-json/wgcr/v1/search محدودیت بگذارید.
  • سقف نتایج: در این نسخه، ثابت WGCR_SEARCH_MAX_RESULTS با مقدار 50 بدون شرط در افزونه تعریف می‌شود؛ بازتعریف آن در wp-config.php پشتیبانی نمی‌شود. از limit بین 1 تا 50 و صفحه‌بندی استفاده کنید.
قبلی استفاده پیشرفته مسیرهای REST API بعدی دسترس‌پذیری و زبان دسترس‌پذیری

صفحه‌های مرتبط

مسیرهای REST APIهمه‌ی مسیرهای REST ویجت‌کور در یک صفحه؛ تنها مسیر عمومی جستجو، کاربردش، قاعده‌های مشترک، قابلیت‌هایی که اصلاً REST ندارند و روش سریع آزمایش آن. ویجت جستجوی زندهراهنمای کامل ویجت جستجوی زنده‌ی WidgetCore؛ کنترل‌های عمومی، طرح‌بندی، کوئری و صفحه‌بندی، ساختار خروجی، رفتار جاوااسکریپت و کار بدون جاوااسکریپت. شورت‌کد جستجوراهنمای کامل شورت‌کد wgcr_search؛ همه‌ی ویژگی‌ها با مقدار پیش‌فرض و مقدارهای مجاز، نمونه‌های کاربردی و تفاوت آن با ویجت المنتور.
