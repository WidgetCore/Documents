پیش‌نیازها و سازگاری

حداقل نسخه‌های وردپرس، PHP و المنتور برای افزونه‌ی WidgetCore، جدول سازگاری آزمایش‌شده، و نکات میزبانی مانند REST API و کش.

آخرین به‌روزرسانی 2026-09-30

پیش از نصب، این صفحه را یک بار مرور کنید. همه‌ی مقادیر اینجا همان مقادیری است که در هدر فایل اصلی افزونه (widgetcore.php) ثبت شده‌اند؛ فقط نسخه‌های آزموده‌شده در فایل readme.txt اعلام می‌شوند.

چرا المنتور لازم است

همه‌ی ویجت‌ها از کلاس Widget_Base المنتور ارث‌بری می‌کنند و در هوک elementor/widgets/register ثبت می‌شوند. اگر المنتور فعال نباشد، فایل‌های ویجت حتی بارگذاری نمی‌شوند؛ بنابراین افزونه هیچ خروجی یا سرباری روی سایت نمی‌گذارد.

آنچه در سمت سرور لازم است

REST API فعال

جستجوی زنده نتایج را از مسیر /wp-json/wgcr/v1/search می‌گیرد. اگر REST API وردپرس با افزونه‌ی دیگری یا با قوانین امنیتی مسدود شده باشد، جستجو پیام خطا نشان می‌دهد. بررسی سریع:

پاسخ باید یک آرایه‌ی JSON از نتایج باشد. اگر rest_cannot_access یا صفحه‌ی خطا گرفتید، REST API مسدود است.

PHP با تابع‌های چندبایتی

پرس‌وجوی جستجو از mb_strlen استفاده می‌کند تا حداقل طول عبارت (2 نویسه) درست بررسی شود. این تابع در نصب‌های استاندارد PHP موجود است. اگر میزبان شما mbstring را غیرفعال کرده باشد، هسته‌ی وردپرس پیاده‌سازی جایگزین فراهم می‌کند و جستجو کار می‌کند.

کش صفحه

افزونه هیچ کش صفحه‌ای نصب نمی‌کند و با افزونه‌های کش سازگار است، چون درخواست جستجو همیشه به REST می‌رود و HTML صفحه کش‌شده روی آن اثری ندارد. دو نکته را در نظر داشته باشید:

  • اگر کش سمت سرور (مانند Varnish) هدرهای X-WP-Total و X-WP-TotalPages را حذف می‌کند، شماره‌ی صفحه‌ها در حالت صفحه‌بندی شماره‌ای درست نمایش داده نمی‌شود.
  • فایل‌های search.css و search.js با شماره‌ی نسخه‌ی افزونه (WGCR_VER) ثبت می‌شوند؛ بنابراین پس از هر به‌روزرسانی، مرورگر نسخه‌ی تازه را می‌گیرد و نیازی به خالی کردن دستی کش نیست.

پشتیبانی از مرورگرها

ویجت‌ها از ویژگی‌های جاوااسکریپتی استفاده می‌کنند که در مرورگرهای به‌روز موجود است:

ویژگیکاربردجایگزین در صورت نبود
fetchدریافت نتایج جستجوپیام خطای دریافت نتایج
AbortControllerلغو درخواست قبلی هنگام تایپ سریعدرخواست‌ها به‌ترتیب پاسخ می‌گیرند
IntersectionObserverپیمایش بی‌نهایت در حالت «صفحه»بارگذاری با کلیک و شماره‌ی صفحه کار می‌کند
prefers-reduced-motionکاهش حرکت انیمیشن‌هاانیمیشن‌ها کامل اجرا می‌شوند

موارد پشتیبانی‌نشده

مواردی که افزونه پوشش نمی‌دهد

  • جستجوی چندزبانه‌ی هم‌زمان: هر ویجت یک منبع (پست‌تایپ) را جستجو می‌کند؛ برای سایت‌های چندزبانه باید در هر زبان یک ویجت جداگانه قرار دهید.
  • جستجو در محتوا با وزن‌دهی سفارشی: پرس‌وجو بر پایه‌ی s وردپرس است؛ برای امتیازدهی پیشرفته باید از فیلتر wgcr_search_query_args استفاده کنید (صفحه‌ی پرس‌وجو و فیلترها).
  • ویرایشگر کلاسیک یا گوتنبرگ: ویجت‌ها فقط برای المنتور ساخته شده‌اند؛ در سایر صفحه‌سازها تنها شورت‌کد [wgcr_search] کار می‌کند.

بررسی سریع قبل از نصب

  1. نسخه‌ی وردپرس و PHP را ببینید

    در «پیشخوان → ابزارها → سلامت سایت» هر دو مقدار نمایش داده می‌شود.

  2. المنتور را فعال کنید

    بدون آن، دسته‌ی «ویجت‌های WidgetCore» در ویرایشگر ظاهر نمی‌شود.

  3. REST API را آزمایش کنید

    آدرس /wp-json/ را در مرورگر باز کنید؛ باید JSON ببینید.

  4. بسته را نصب کنید

    طبق راهنمای نصب و فعال‌سازی.

قبلی آشنایی مفهوم‌های پایه بعدی دریافت و نصب دانلود

صفحه‌های مرتبط

نصب و فعال‌سازیراهنمای گام‌به‌گام نصب افزونه‌ی WidgetCore در وردپرس با سه روش (بارگذاری ZIP، FTP و WP-CLI)، فعال‌سازی، بررسی ویجت‌ها در المنتور و حذف افزونه. عیب‌یابیراهنمای عیب‌یابی افزونه‌ی WidgetCore؛ ویجت دیده نمی‌شود، جستجو نتیجه نمی‌دهد، استایل‌ها بهم ریخته‌اند، به‌روزرسانی کار نمی‌کند و مشکلات عملکرد، همراه با روش تشخیص هر مورد. دانلوددانلود بسته‌ی نصب WidgetCore از انتشارهای گیت‌هاب، محتویات بسته، راه‌های جایگزین دریافت و راهنمای انتخاب نسخه‌ی مناسب.
