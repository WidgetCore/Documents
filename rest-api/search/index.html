The search REST endpoint

The WidgetCore search REST endpoint — the route, every parameter with its type and default, the response shape, pagination headers, request examples and the status codes.

Last updated 2026-09-30

The search widget and the shortcode both talk to a single REST endpoint. You can call it yourself from JavaScript, from a mobile app or from another plugin.

The endpoint

ItemValue
Namespacewgcr/v1
Route/search
Full addresshttps://example.com/wp-json/wgcr/v1/search
MethodGET
Permission callback__return_true (public)
Result capWGCR_SEARCH_MAX_RESULTS (50)

Why the route is public

Search results only ever contain published posts without passwords, which any visitor can already reach through the theme's search page. Making the route public removes the need for nonces and lets you use the endpoint from any client.

These are the default query guarantees. Custom wgcr_search_query_args filters run after the base arguments are built and can change them: preserve post_status => publish, has_password => false, public searchable post types and sensible limits. The public route does not reapply those constraints after filters.

Parameters

ParameterTypeDefaultDescription
qstring—Required; the search query, at least 2 characters
typestringpostOne public, searchable post type; attachment and elementor_library are excluded; invalid values fall back to post
limitnumber5Number of results; clamped to 1–50
templatenumber0Elementor template id used to render results
pagenumber0Page number; when greater than 0 the count headers are returned
orderbystringrelevancerelevance, date, title, author, rand, menu_order. rand is reshuffled on every request, so with page a result can repeat on another page or be skipped
orderstringDESCASC or DESC
datestringallall, week, month, year
termsstringEmptyA comma separated list of [taxonomy:]id
terms_opstringexcludeinclude or exclude
ignore_stickynumber11 means sticky posts are not given priority. With 0, sticky posts are moved to the top of the current page of results only, not across pages
query_idstringEmptyThe key for the wgcr_search_query_args/{query_id} filter

q validation: if it is not a string, or shorter than 2 characters after trim, the response is a rest_invalid_param error.

The response shape

FieldTypeNotes
idnumberPost id
titlestringTitle with tags removed and HTML entities decoded
linkstringPermalink
thumbstringThumbnail URL, an empty string when there is none
excerptstringTags and shortcodes removed, trimmed to 18 words with an ellipsis when truncated; HTML entities decoded
datestringPublish date in the site’s configured date format (get_the_date)
htmlstringOptional: visible output from a published elementor_library template, with Elementor available

The six base fields are always returned. thumb and excerpt display controls affect the browser rendering, not the REST payload; there are no REST parameters to omit these fields. The sample date is illustrative, not a fixed wire format. There is no built-in “All post types” source.

Pagination headers

When page is greater than 0, two standard WordPress headers are added to the response:

HeaderMeaning
X-WP-TotalTotal number of matching posts
X-WP-TotalPagesTotal number of pages at the requested limit

Caches can strip headers

A server-level cache such as Varnish may drop custom response headers. If numbered pagination cannot compute the page count, check these headers in your browser's network tab.

Examples

One request, four flavours — pick the tab that matches your stack.

curl -s "https://example.com/wp-json/wgcr/v1/search?q=course&limit=5&type=post"

# With pagination, reading the count headers
curl -sD - -o /dev/null "https://example.com/wp-json/wgcr/v1/search?q=course&limit=12&page=2" | grep -i "^x-wp"
const url = new URL('/wp-json/wgcr/v1/search', window.location.origin);
url.searchParams.set('q', 'course');
url.searchParams.set('limit', '8');
url.searchParams.set('page', '1');

const res = await fetch(url, { headers: { Accept: 'application/json' } });
const items = await res.json();
const total = Number(res.headers.get('X-WP-Total') || 0);
const pages = Number(res.headers.get('X-WP-TotalPages') || 0);

items.forEach((item) => {
	console.log(item.title, item.link, item.thumb);
});
url.searchParams.set('terms', 'category:12,category:18');
url.searchParams.set('terms_op', 'include');
url.searchParams.set('orderby', 'date');
url.searchParams.set('order', 'DESC');
url.searchParams.set('template', '1482');

When template is valid, every result carries an extra html field with that template rendered for that post. If the template is a draft or renders no visible content, html is not returned.

Server-side behaviour

StepWhat happens
1q is validated (at least 2 characters)
2type is sanitised; invalid values become post
3limit is clamped to 1…WGCR_SEARCH_MAX_RESULTS
4orderby, order, date, terms, terms_op are whitelisted
5The query args are built: post_status => publish, has_password => false
6The wgcr_search_query_args filter runs, then the {query_id} variant
7WP_Query runs and the results are mapped into the response fields
8With template, each post is rendered through Elementor
9With page > 0, the count headers are added

Status codes

StatusWhen
200A successful search (an empty array is still a success)
400Missing q: rest_missing_callback_param; invalid type or fewer than 2 characters: rest_invalid_param
404The REST API itself is unavailable or permalinks block it

An empty result is not an error: you get 200 with [], and the client shows the “No results found.” message.

Rate limiting and optimisation

The plugin adds no rate limiting of its own. On a busy site consider these measures:

MeasureEffect
Cache the route for anonymous users (short TTL)Fewer queries for popular terms
Keep limit at or below 12Smaller payloads
Turn thumbnails offFewer image requests
Add an index for your search-heavy post typeFaster WP_Query
Use query_id + a filter to narrow the query before it runsLess work in the database

Do not cache per-user results

Default results are public. Any REST cache must vary by the complete query string and preserve pagination headers. If custom filters make results user-dependent, avoid shared caching or vary by that context too. Hiding thumbnails only prevents image requests; it does not remove the thumb field from JSON.
