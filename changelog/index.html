What changed in every released version of the WidgetCore plugin, newest first.

Last updated 1 October 2026

v0.0.8Comments widget and responsive size controlsLatest

Release date: 30 September 2026

Adds the Comments widget and the [wgcr_comments] shortcode, makes every size control in the Style tab of all three widgets responsive with Normal and Hover tabs, and removes the theme's duplicate comment list and form when the widget is used.

  • New Comments widget (wgcr-comments): the approved comments of the current post with replies, optional pagination and avatars, plus a configurable comment form — choose the fields, labels, required state and notes, with a full Style tab.
  • New [wgcr_comments] shortcode for the same list and form outside Elementor; it accepts every widget control as an attribute and falls back to the default for invalid values.
  • Comments are sent to WordPress' own comment handler, so moderation, spam checks, flood protection and the login requirement from Settings → Discussion keep working; the widget can make name and email optional, and can only make login stricter, never looser.
  • The widget stores nothing of its own (no option, table or cookie) and loads no script; its stylesheet is enqueued only on pages that print it. Avatars come from Gravatar through WordPress and can be hidden.
  • When the widget or shortcode prints for a post, the theme's own comment list and form are no longer printed next to it (classic themes and block themes), so each post shows a single list and a single form.
  • Comments Style tab: new avatar width, avatar distance from the comment card, per-corner avatar radius, and author-name and date distance from the avatar controls.
  • Comments Style and Content: a reply now lives inside its parent comment's card, and "Reply indent and spacing" is a four-side margin relative to that card (top spacing plus indent, per device). The logged-in user text ("Logged in as …") has its own Messages controls — text with a {name} placeholder, optional profile and log-out links — and its own Style section. The avatar radius, distance and position now apply even when the theme styles #comments .comment .avatar.
  • All widgets (FAQ, Live Search, Comments): every size control in the Style tab — widths, heights, padding, margins, gaps, radius, icon and avatar sizes — is now responsive (desktop, tablet, mobile) and has Normal and Hover tabs.
  • Live Search: the shortcode and the widget now read their defaults from a single place, so they can no longer drift apart.

v0.0.7Updates from GitHub

Release date: 26 September 2026

WidgetCore now updates itself from its GitHub releases through WordPress' own update system, with release notes in the plugin details screen.

  • Updates straight from the GitHub repository — the Update URI header plus WordPress core hooks, with no extra library: the latest release of WidgetCore/Plugin and its widgetcore.zip asset.
  • The release notes of each version are shown in the plugin's “View details” screen, and the native per-plugin auto-update toggle works for WidgetCore.
  • A “Check for updates” action link in the plugins list, with a notice reporting the result.
  • An optional WGCR_GITHUB_TOKEN constant for private repositories. If the header is removed later, updates switch back to the official WordPress plugin directory.

v0.0.6Cleaner Live Search template results

Live Search results built with an Elementor template now come entirely from your template, and Page-mode result lists grow with their results.

  • Live Search: results rendered with an Elementor template no longer receive the widget's card wrapper or styles — no nested links, no padding, hover or selection styles, and mouse hover never marks a result (keyboard navigation keeps an outline-only indicator).
  • Live Search: in Page display mode the results panel is unstyled as well, so everything comes from your template.
  • Live Search: Page-mode result lists now grow with their results (the container max-height control scrolls the panel), and infinite scroll observes the viewport.
  • Every published package carries its own version number, so browsers never reuse a cached search.css or search.js from an older build.

v0.0.5Live Search queries, pagination and columns; keyboard-friendly FAQ

Makes the Live Search Query, Pagination and Columns controls work, adds Masonry and Equal height in Page mode, improves keyboard support in the FAQ widget, and switches the plugin to a per-release version counter.

  • Versioning: the plugin now uses a per-release counter (0.0.1 → 0.0.2 … 0.0.9 → 0.1.0 … 0.9.9 → 1.0.0); earlier entries were renumbered accordingly.
  • Live Search: the results count is driven by “Items per page” in the Layout section (1–50, default 12); the old “Results count” control in General was removed. Widgets that saved the old value keep it until “Items per page” is set once.
  • Live Search: the “Columns” control now works — in Page display mode results render as a responsive CSS grid (desktop / tablet / mobile, defaults 3 / 2 / 1). List mode stays single-column and hides the control.
  • Live Search: “Custom post type” moved from the Query list into the Source select; choosing it there reveals the slug field, and the slug no longer overrides an explicitly selected source.
  • Live Search: Page-mode “Results container” style controls now live inside the “Results panel” section and appear only in Page display mode; horizontal alignment no longer overrides the margin control.
  • Live Search: the Query controls are applied — include/exclude terms from any public taxonomy, date range, order by (relevance, date, title, author, random, menu order) and order, sticky posts first, plus a Query ID for the wgcr_search_query_args/{query_id} filter. Matching REST parameters and shortcode attributes were added.
  • Live Search: the Pagination controls are applied — page numbers, previous/next, a “load more” button (text, icon, ID) and infinite scroll inside the results panel, with alignment, spacer and a custom “no more posts” message.
  • Live Search: “Masonry” and “Equal height” now work in Page display mode.
  • Live Search: template <link> stylesheets load as real stylesheets (once per page) instead of being inlined as text; the “view all” arrow, hover shift and selection bar follow the text direction, and motion is reduced for prefers-reduced-motion.
  • Live Search: template and term option lists are queried only inside the Elementor editor, not on every front-end render.
  • Live Search: the shortcode limit accepts 1–50 and a new columns attribute (page mode); the REST limit cap was raised to 50 (WGCR_SEARCH_MAX_RESULTS).
  • FAQ: closed answers leave the tab order, Arrow Up/Down, Home and End move between questions, inline editing works in the editor preview, and reduced motion is respected.
  • Shared SVG icons (wgcr_svg_icon()) replace the duplicated icon helpers of both widgets.
  • Verified against WordPress 7.1.2 with Elementor 4.3.2, and WordPress 6.7.4 with Elementor 4.0.8.

v0.0.4Live Search Elementor template results

Live Search results built from an Elementor template now keep the template's own CSS and animations, and the results-container width and alignment controls were fixed.

  • Live Search: results built from an Elementor template now carry the template's own CSS (inlined once per response), so custom templates render styled in both display modes.
  • Live Search: injected template results are initialized with Elementor's front-end handlers and elementor-invisible entrance-animation placeholders are resolved, so animated templates no longer appear empty.
  • Live Search: a template that renders without visible content falls back to the default result card instead of returning empty items.
  • Live Search: the results-container width and alignment controls were fixed — both now apply to the results box itself instead of the whole widget, with the field gap preserved in Page mode.

v0.0.3Rebuilt Live Search settings

Live Search settings were rebuilt into General, Layout, Query and Pagination sections, and Page display mode and template rendering were hardened.

  • Live Search: content settings were rebuilt into General (display mode first), Layout, Query and Pagination sections, matching Elementor's own loop widgets. Layout adds a template-type selector with custom post type support, a searchable Elementor template picker with an edit link, columns, items per page, masonry, equal height and an alternate template. Query adds include/exclude terms, date range, orderby/order, a sticky control and a query ID. Pagination adds type, alignment, a load-more button and custom messages. Style adds a results-container section (width, height and more) for Page mode.
  • Live Search: Page display mode (results container styling) was fixed and REST template rendering was hardened, so a broken Elementor template can no longer fail the whole search request.

v0.0.2Live Search Page display mode

Live Search gains a Page display mode that shows the results in a permanently visible region, also available in the shortcode.

  • Live Search: added a display_mode option (Modal / Page). In Page mode results render in a permanently visible region inside the widget container instead of the dropdown panel.
  • The [wgcr_search] shortcode accepts a mode="page" attribute.

v0.0.1Initial release: FAQ and Live Search

First public version of WidgetCore with the FAQ widget, the Live Search widget and its shortcode, bundled Persian and English translations.

  • Initial release: the FAQ widget (wgcr-faq) with FAQPage schema, and the Live Search widget (wgcr-search) with the [wgcr_search] shortcode.
  • Full internationalisation support, with Persian (fa_IR) and English (en_US) translations bundled in the plugin.
  • Built to the WordPress plugin coding standards (late escaping, no heredoc, prefixed globals).
  • Licensed under GPL-2.0-or-later.
  • Compatibility with the latest WordPress and Elementor releases is checked before every release build.
