Comments widget

The complete guide to the WidgetCore Comments widget — comment list and form for the current post, optional fields, required name and email, field order, pagination, avatars, shortcode and styling.

Last updated 8 October 2026

The Comments widget shows the current post's comment list and the comment form in one widget. Saving, spam checks, manual approval and notification emails stay the job of WordPress itself; the widget only gives you control over the look, the layout and the form fields. It needs no other plugin, ships no JavaScript of its own and creates no page or option in the dashboard.

Quick start

  1. Drag the widget

    On a single-post template (or any page that needs comments) drop “Comments” from the “WidgetCore Widgets” category.

  2. Choose the fields

    In the “Fields” section turn name, email, website and the save-in-browser checkbox on or off and translate the labels.

  3. Set the look

    In the Style tab change the colours, borders, spacing and typography of each part.

  4. Try it on the site

    Send a test comment; instant publishing or manual approval is decided by Settings → Discussion in WordPress.

In the Elementor editor

In the editor the widget shows three fixed sample comments so you can see the list, and the form is disabled (nothing is submitted). Real comments appear only on the site.

“Logged-in users only” can only be stricter

If WordPress (Settings → Discussion) requires users to be logged in, the widget cannot allow guests. The other way round, turning this switch on keeps posting limited to members even when WordPress allows guests.

  • The comment text cannot be removed or made optional.
  • Website is always optional.
  • The “save in browser” checkbox only appears when WordPress' own option for it (Settings → Discussion) is on; the control can only turn it off or change its text.
  • Logged-in users do not see the name, email, website or checkbox fields; they get “Logged in as …” with profile and log-out links instead; the text and the links are editable in the “Messages” section.
  • The field order is changed in the HTML itself, so the Tab key order always matches the visual order.

How required fields work

Every form sends a signed hidden field that tells WordPress whether name and email are required in this form. Without that field WordPress behaves exactly as its own settings say. As a result:

  • You can make name and email optional even when WordPress requires them (for this form only).
  • You can make email required even when WordPress does not.
  • If an email is entered, its format must be valid.
  • A direct post to WordPress' core endpoint (for example by a bot) without this field is checked against the WordPress settings; the widget does not close that path.

  • Threading, reply depth, pagination and the default order are decided by WordPress (Settings → Discussion); “Comments per page” and “List order” let this widget override them for itself.
  • Pagination prints “Previous”, “Next” and page numbers; the current page is announced to screen readers.

Avatars and privacy

When avatars are shown, WordPress loads the image from the Gravatar service and the visitor's browser makes a request to that domain. If you do not want that, set “Avatar” to “Hide”. The plugin itself makes no external request.

SituationOutput

Comments closedThe list stays; the message “Comments are closed for this post.” replaces the form

Password-protected postNothing is shown
Private post or draftOnly for someone allowed to see it
A post type without commentsNothing is shown

One form per page

WordPress' comment form has identifiers that must not repeat on a page. If you put several comments widgets or shortcodes on one page, the first prints the form and the rest print only the list.

The theme's comments are not printed next to the widget

Once the widget or shortcode has printed something for the current post, the plugin stops the theme's own comment area from printing for that post: both comments_template() in classic themes and the comments blocks in block themes. Each post then has exactly one list and one form, and both come from the widget. This only applies to the post the widget printed for: a widget that points to another post with post does not hide the current post's comments, a password-protected post stays with the theme, and the editor preview hides nothing. There is no option for this behavior.

Very large lists

The widget reads all approved comments of the post at once and paginates them itself. For posts with tens of thousands of comments, use the widget for the form and turn the list off with “Show list”.

Shortcode

  • Every attribute uses the same ID as the tables above (for example author="no", per_page="10", order="desc"). Show/required values are yes and no.
  • One extra attribute, post: the ID of another post; it defaults to the current post.
  • An invalid value silently falls back to the default.
  • The Style tab options exist only in the widget; the shortcode uses the default look. Change it with custom CSS and the classes below.

Accessibility

  • Every field has a real label, and required fields are announced with required and aria-required; the required asterisk is hidden from screen readers.
  • The submit button is a real button, and the Tab order matches the visual order.
  • The pagination navigation has an aria-label and the current page has aria-current="page".
  • The focus ring is drawn for :focus-visible; forced-colors mode and prefers-reduced-motion are supported.
  • The layout uses CSS logical properties, so it works in Persian (right-to-left) and English (left-to-right).

Troubleshooting

ProblemLikely causeFix
The widget shows nothingThe post is password-protected or private, its type has no comments, or the widget is outside a postPlace it in a single-post template; give post in the shortcode
The theme's form or list shows up as wellThe theme's comment area prints for a post the widget printed nothing for (the widget points to another post, the post is password-protected, or the widget sits in another post), or the page is an old cached copyPut the widget in this post's own content and leave post empty; clear the cache
The second form is missingA page has only one formKeep one form per page; give the other instances form="no"
“Please fill in the required fields.”A required field is empty or the email is malformedFill it in, or turn its required switch off
Guests cannot commentWordPress or “Logged-in users only” requires loginCheck Settings → Discussion
Making name or email optional has no effectAn old cached copy of the page, or the form is submitted from elsewhereClear the cache
A comment is not visible after sendingManual approval or WordPress' disallowed listSettings → Discussion; a guest sees it as “awaiting moderation” for ten minutes after sending (or longer if the save-in-browser checkbox was ticked)
The avatar image loads from another siteWordPress' Gravatar behaviourSet “Avatar” to “Hide”
