Shortcodes

Every WidgetCore shortcode on one page — [wgcr_search] and [wgcr_comments], what each one is for, the rules they share, examples and links to the complete guide of each shortcode.

Last updated 1 October 2026

Shortcodes place WidgetCore widgets anywhere on your site without Elementor: inside post or page content, in a theme template, or with do_shortcode() in PHP. This page lists every shortcode and the rules they share. A shortcode that needs a longer explanation has its own page under this one.

All shortcodes

ShortcodeWidget equivalentUseComplete guide
[wgcr_search]Live SearchA live search field with results in a popup or on the pageThe wgcr_search shortcode
[wgcr_comments]CommentsThe comment list and the comment formThe section below and the Comments widget

The FAQ widget has no shortcode; it works in Elementor only.

Rules they share

  • Every attribute is optional. An attribute you leave out takes its default value.
  • Yes/no values: yes, 1, true and on count as “yes”; any other value is “no”. This is the same in both shortcodes.
  • An invalid value never raises an error. A wrong or out-of-range value silently falls back to the default or to the nearest allowed value.
  • Styling: the Style tab sections exist only in the Elementor widget. A shortcode uses the default look and can be changed with custom CSS.
  • Assets load only on a page where the shortcode is printed.

The search shortcode

[wgcr_search] is the Live Search widget. The result source (source), the count (limit), the display mode (mode), columns, terms, date range and order are set with attributes.

The complete table of 24 attributes, the allowed values, the PHP function, the differences from the widget and value validation are on the The wgcr_search shortcode page.

The comments shortcode

[wgcr_comments] puts the comment list and form outside Elementor. Its attributes use the same IDs as the widget controls (form, list, title, author, email, url, cookies, author_required, email_required, rows, submit, per_page, order, avatar, reply, login_only, post and more). The full list with defaults is on the Comments widget page.

  • The extra attribute post is the ID of another post; it defaults to the current post.
  • Only one comment form is printed per page; later instances print just the list.
  • Saving a comment, spam checks and approval are still done by WordPress itself; the shortcode only sets the look and the fields of the form.
